# Code Dungeon stand-up Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `npm run dev` in `H:\codedungeon` starts a real Code Dungeon office on ports 4417/5417, with its data in `H:\codedungeon-home`. The code lives in its own git repo with a private GitHub remote, and it can never touch the live cubefarm office.

**Architecture:** Bring cubefarm's history in with git (from `H:\cubefarm`, branch `local/all-fixes`). Put Code Dungeon's ports, data folder and a guard in one small plain-JS module, `shared/dungeon.mjs`, that the server, launcher, Vite, Vitest and Playwright all read. The launcher also points temp files, the npm cache and the Playwright browsers at the H: data folder for itself and every agent it starts.

**Tech Stack:** Node 22+, TypeScript (tsx), Vite 8, Vitest 5, Playwright, git, GitHub CLI (`gh`).

**Spec:** `docs/superpowers/specs/2026-10-02-standup-design.md`

## Global Constraints

- Never write to `H:\cubefarm`, never use ports 4317 or 5317, and never read or write `C:\Users\snake\.cubefarm` (a read-only modified-time check during verification is the one exception).
- No work on C:. Data, temp files, the npm cache and the Playwright browsers go under `H:\codedungeon-home`.
- Server port 4417, Vite port 5417, data folder `H:\codedungeon-home` (the folder named `codedungeon-home` next to the repo).
- `npm run dev` is the real office. There is no `demo` script. The server's `--demo` flag stays, for the automated tests only.
- The launcher's self-update is disabled.
- `package.json`: `"name": "codedungeon"`, `"private": true`.
- Git: local branch `main`. `origin` is the new **private** repo `brainit-consulting/codedungeon`; `upstream` is `https://github.com/leonvanzyl/cubefarm.git`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- `SWARM_PORT=4317` left in the shell environment → the office refuses to start (Task 2 test plus a live check in Task 6).
- `SWARM_HOME` pointing at `~/.cubefarm` in different letter case or with a trailing slash → refused (Task 2 tests).
- `SWARM_HOME` anywhere else on C: → refused (Task 2 test).
- Port `0`, which Vitest uses → allowed (Task 2 test).
- An e2e run must not hit Code Dungeon's own office on 4417/5417 → `playwright.config.ts` refuses those ports too (Task 3).

`shared/dungeon.mjs`:

```js
// Code Dungeon's own ports and data folder, and the guard that keeps it off the live cubefarm office
// (ports 4317/5317, data in ~/.cubefarm) and off the C: drive. Plain JavaScript so the launcher runs it
// without tsx; types are in dungeon.d.mts.
import path from 'node:path';

export const SERVER_PORT = 4417;
export const CLIENT_PORT = 5417;
const LIVE_PORTS = [4317, 5317];

/** The data folder beside the repo: H:\codedungeon → H:\codedungeon-home. */
export function defaultHome(repoRoot) {
  return path.resolve(repoRoot, '..', 'codedungeon-home');
}

/** Why the office must not start with these ports and data folder, or null when it may. */
export function liveOfficeConflict({ ports, home, userHome, platform = process.platform }) {
  const port = ports.find((p) => LIVE_PORTS.includes(p));
  if (port) return `Port ${port} belongs to the live cubefarm office. Code Dungeon uses ${SERVER_PORT} and ${CLIENT_PORT}.`;
  const p = platform === 'win32' ? path.win32 : path.posix;
  const fold = (s) => (platform === 'win32' ? s.toLowerCase() : s);
  const resolved = p.resolve(home);
  if (fold(resolved) === fold(p.resolve(userHome, '.cubefarm'))) return `${resolved} is the live cubefarm office's data. Code Dungeon keeps its own in codedungeon-home.`;
  if (platform === 'win32' && /^c:/i.test(resolved)) return `${resolved} is on the C: drive. Code Dungeon keeps its data on H:.`;
  return null;
}
```
